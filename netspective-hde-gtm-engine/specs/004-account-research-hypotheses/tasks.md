# Tasks: Account Research and Hypotheses

## Progress notes

- All tasks done. Quickstart V1–V22 are covered by the automated integration, contract and scenario tests (T067); no separate manual run was made.
- Deviations: the summary is assembled deterministically from verified findings, so there is no separate synthesise prompt; analyst-pasted text travels in the job payload; recurring `research.schedule` (hourly) and `hypotheses.staleness` (daily) ticks live in `apps/api/src/main.ts`; `ai_invocation` gained `account_id` so the monthly cap counts failed and interpretation calls; quote text is hash-only for citation-only sources; billed cost is clamped to the pre-checked bounds; `duplicate_in_run` does not occur in practice because addresses are de-duplicated at start.
- Known limit: the web fetch adapter cannot fully prevent DNS rebinding (off by default).
- Feature 001 coverage: T096, T098, T100, T103 and T107 are covered in part by 004 (research and LLM interfaces, fakes, wrapper, gateway and its tests); T104–T106 and the other provider interfaces stay open.
- README at the repository root is only a title, so there was no feature list to update.
- Feature 004 UI note: the workspace route `/accounts/[id]/workspace` has no nav entry; it is reached from account links.

**Input**: Design documents from `/specs/004-account-research-hypotheses/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md)

**Tests**: Included and written first. Constitution Principle XVII forbids shipping automated behaviour without unit, contract and scenario tests. Every rule task is preceded by its test task and the test must fail before the rule is implemented. The AI schemas and the prompt-injection fixtures come first, as requested.

**Organization**: Setup → Foundational (schemas and injection fixtures first, then schema and seed) → LLM gateway hardening → research run job → verified summary and signal hand-off → incremental research → hypothesis lifecycle with RBAC review → problem interpretation → APIs → workspace UI → cost cap enforcement → audit/events/privacy checks → scenario tests and polish. All paths are relative to `netspective-hde-gtm-engine/`.

## Format: `- [ ] T### [P?] [US#?] Description with file path`

- **[P]**: can run in parallel (different files, no unfinished dependency)
- **[US#]**: spec user story (US1 bounded run, US2 structured summary and signals, US3 unknowns stay unknown, US4 untrusted content, US5 create or accept hypotheses, US6 reviewer-only status, US7 problem interpretation, US8 incremental runs, US9 workspace)
- **Standard DoD** (applies to every task): lint, format and typecheck pass; the listed tests pass; no secret, PHI-like string or real data introduced (synthetic data only, `.example` hosts); every state change writes an audit event **in the same transaction**; no new column without a `COLUMN_CLASSIFICATION` entry; no fetched text, quote, prompt, response or injection text in logs, audit or events (identifiers, counts and rule ids only); no real model or network call anywhere in tests.
- Constraint text quoted from [data-model.md](data-model.md) is verbatim. Numeric defaults (10 sources, 2.00 per run, 20.00 per account per month, 2 retries, 90-day staleness, 10 s fetch timeout, 1 MiB page limit, 0.20 per interpretation) are **hypotheses**, configurable and labelled as such.
- Test files follow the layout of features 001–003 (domain tests under `packages/domain/test/`, integration under `apps/api/test/*.int.test.ts`, contracts under `apps/api/test/contract/`, DB tests under `packages/db/test/`, web tests under `apps/web/test/`).

## Ordering notes

- The requested order is followed. Two refinements: the **per-run worst-case budget check** is built with the gateway (it is part of making any call), while the **per-account monthly cap** and the end-to-end proof that no run exceeds its budget are in the requested late "cost cap enforcement" phase; verification and hand-off are separate from the runner skeleton so the run job can be tested first.
- **The gateway does not exist yet in the repository** (feature 001 tasks T096–T109 are open; `packages/providers` is empty), so Phase 3 builds the minimal slice (interfaces, fakes, wrapper, prompt registry, `ai_invocation`, gateway). This covers parts of 001 T096, T098, T100, T103–T107; the rest of 001's US7/US8 stays open.
- Dependencies on earlier features: feature 003's `SignalService.ingestSubmission`, `resolveAccountScope` and review/current-evidence reads (merged to `main`); feature 002's accounts. The workspace's ICP panel shows "not assessed" until feature 002's evaluator exists.
- The attention queue is the list of runs in `needs_attention` (not `review_item`, which cannot take a new kind without a table rebuild).

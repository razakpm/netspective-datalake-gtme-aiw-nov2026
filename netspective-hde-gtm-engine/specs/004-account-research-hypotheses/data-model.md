# Data Model: Account Research and Hypotheses

Interim SQLite (ADR-015); migrations `0014`–`0016`, forward-only. Types are SQLite types; the Postgres port will use `uuid`, enums, `jsonb` and `timestamptz`. All ids are UUID v7 text; all timestamps are ISO-8601 UTC text. Money is integer micro-units (`*_micros`). "Append-only" tables get `BEFORE UPDATE`/`BEFORE DELETE` triggers raising an error. Classification: **BC** business_contact, **CC** confidential_commercial, **SOM** sensitive_operational_metadata. Every column is registered in `COLUMN_CLASSIFICATION`. **No column anywhere may hold fetched page text beyond a short permitted excerpt, a reasoning trace, a prompt or response body, a numeric confidence score, or a qualification/funding/ICP-fit/eligibility value** (a schema scan test checks column names). Feature 003's `signal` table is not changed.

## Relationships

```text
account 1─* research_run 1─* research_source_fetch 1─* research_finding ─> signal (feature 003, via ingest)
research_run 1─* ai_invocation (context_type = research_run)     prompt_version 1─* ai_invocation
account 1─0..1 research_schedule        research_source_rule 0..1─* research_source_fetch
account 1─* account_hypothesis 1─* hypothesis_evidence *─1 signal        hypothesis 1─* hypothesis_status_decision
hypothesis 1─* hypothesis_assumption ─> problem_interpretation (optional)   hypothesis 1─* hypothesis_tag
research_run 1─* account_hypothesis (proposals)     * confidence_assessment ─> finding | hypothesis | interpretation
```

## State transitions

- **Run**: `queued → running → completed | budget_reached | needs_attention | failed | cancelled`; `queued → cancelled`; `needs_attention → (acknowledged)` keeps the state and records who/when/note. Cancellation is cooperative: checked before each fetch and model call.
- **Source fetch outcome**: set once when the fetch row is written; no later change.
- **Hypothesis acceptance**: `proposed → accepted | dismissed` (human; accept sets `status = untested`); `analyst-created → accepted` at insert; `dismissed` is final.
- **Hypothesis status** (accepted only, reviewer + note, see research R-11): `untested → strengthening | weakening | rejected | validated`; `strengthening ⇄ weakening`; `strengthening | weakening → rejected | validated`; `validated → weakening | rejected`; `rejected → untested`; `stale → untested | strengthening | weakening`; any of `untested | strengthening | weakening → stale` by the staleness rule only.
- **Flag for review** (supporting signal rejected, stale or contradicted): worked out live by the read models and materialised (`flagged_for_review 0 → 1`) by the daily job; cleared by any status decision or an explicit "reviewed" action.
